> 本文档面向其他 AI 或新开发者，提供项目全貌、技术栈、架构约定和编码规范，确保产出的代码风格一致、可直接合并。

## 一、项目概述

**NI** 是一款使用 **Rust + Bevy 0.18** 引擎开发的 3D 冒险游戏。玩家在 3D 场景中探索、收集金色光球、躲避敌人、与 NPC 对话，完成多个关卡。同时内置**塔防模式**和 **Solari 光追演示关卡**。

| 属性 | 值 |
|------|-----|
| 项目名称 | NI（从零开始的 3D 冒险） |
| 语言 | Rust (edition 2024) |
| 引擎 | Bevy 0.18（ECS 架构） |
| UI 框架 | egui (bevy_egui 0.39) |
| 序列化 | serde / RON |
| 仓库 | github.com/xiaogua-123/3d-by-rust |
| 项目路径 | `E:\游戏制作项目\从0开始 - 3d\ni` |

### 4.2 状态机

两个状态枚举控制整个游戏流程：

```rust
// 游戏阶段（控制 UI 和逻辑开关）
enum GamePhase {
    MainMenu, Playing, Paused, Dialoguing, GameOver, LevelComplete, MultiplayerChat
}

// 关卡选择（控制场景加载/卸载）
enum GameLevel {
    None, Level1, Level2, Level3, Level4, Level5, Solari
}
```

- `OnEnter(GameLevel::X)` → 生成关卡场景
- `OnExit(GameLevel::X)` → 清理关卡实体（通过 `LevelEntity` 标记）
- 大多数游戏系统以 `run_if(in_state(GamePhase::Playing))` 守卫

### 4.3 事件系统（Message）

使用 Bevy 0.18 的 `Message` trait（替代旧版 `Event`）：

```rust
#[derive(Message)]
pub struct SomeEvent { ... }

// 注册
app.add_message::<SomeEvent>();

// 写入
fn system(mut writer: MessageWriter<SomeEvent>) { writer.write(SomeEvent { ... }); }

// 读取
fn system(mut reader: MessageReader<SomeEvent>) { for ev in reader.read() { ... } }
```

**核心事件列表：**

| 事件 | 发送方 | 消费方 | 用途 |
|------|--------|--------|------|
| `StartGameEvent` | 主菜单 | game_state | 开始新游戏 |
| `RestartGameEvent` | 游戏结束 | game_state | 重新开始 |
| `NextLevelEvent` | 关卡完成 | game_state | 下一关 |
| `MainMenuEvent` | 暂停/结束 | game_state | 返回主菜单 |
| `CollectItemEvent` | 收集品 | game_state | 拾取物品 |
| `DamagePlayerEvent(u32)` | 敌人 | game_state | 玩家受伤 |
| `LevelCompleteEvent` | 收集品 | game_state | 关卡完成 |
| `LoadLevelEvent` | Zone 过渡 | level | 加载关卡 |
| `ResetPlayerEvent` | Zone 过渡 | player | 重置玩家位置 |
| `StartDialogueEvent` | NPC 交互 | dialogue | 开始对话 |
| `DialogueAdvanceEvent` | 对话 UI | dialogue | 推进对话 |
| `DialogueChoiceEvent(usize)` | 对话 UI | dialogue | 选择选项 |

### 4.4 插件模式（必须遵守）

每个功能模块定义为独立的 Plugin：

```rust
// 文件: src/my_feature.rs
use bevy::prelude::*;

pub struct MyFeaturePlugin;

impl Plugin for MyFeaturePlugin {
    fn build(&self, app: &mut App) {
        app
            // 1. 注册类型（如需编辑器检查）
            .register_type::<MyComponent>()
            .register_type::<MyResource>()
            // 2. 注册状态（如需）
            // .init_state::<MyState>()
            // 3. 初始化资源
            .init_resource::<MyResource>()
            // 4. 注册事件
            .add_message::<MyEvent>()
            // 5. 添加系统
            .add_systems(Startup, my_startup)
            .add_systems(Update, (
                my_system_a,
                my_system_b,
            ).run_if(in_state(GamePhase::Playing)));
    }
}
```

然后在 `main.rs` 中注册：
```rust
mod my_feature;
use my_feature::MyFeaturePlugin;

app.add_plugins(MyFeaturePlugin);
```

## 五、编码规范

### 5.1 组件定义

```rust
// 标准组件（含 Reflect，可在 Inspector 中查看）
#[derive(Component, Reflect)]
#[reflect(Component)]
pub struct Player;

#[derive(Component, Reflect, Default)]
#[reflect(Component)]
pub struct Velocity {
    pub y: f32,
}

// 标记组件（无字段）
#[derive(Component, Reflect)]
#[reflect(Component)]
pub struct Model;  // 子实体标记

// 不需要 Inspector 的组件（如 TD 内部组件）
#[derive(Component)]
pub struct Turret { ... }

// 需要克隆的组件
#[derive(Component, Reflect, Clone)]
#[reflect(Component)]
pub struct DialogueTrigger { ... }
```

**规则：**
- 必须 `#[derive(Component)]`
- 游戏逻辑组件加 `#[derive(Reflect)]` + `#[reflect(Component)]`
- 有合理默认值的加 `#[derive(Default)]`
- 标记组件用单元结构体

### 5.2 资源定义

```rust
// 标准资源（可在 Inspector 中查看）
#[derive(Resource, Reflect)]
#[reflect(Resource)]
pub struct MyConfig {
    pub speed: f32,
}

// 运行时状态资源（不需要 Inspector）
#[derive(Resource, Default)]
pub struct MyRuntimeState {
    pub active: bool,
}

// 需要自定义默认值的资源
#[derive(Resource)]
pub struct MyData {
    pub values: Vec<f32>,
}

impl Default for MyData {
    fn default() -> Self {
        Self { values: vec![1.0, 2.0, 3.0] }
    }
}
```

**规则：**
- 必须 `#[derive(Resource)]`
- 可检查的加 `#[derive(Reflect)]` + `#[reflect(Resource)]`
- 优先 `#[derive(Default)]`，用 `.init_resource::<T>()` 注册
- 需要构造函数的用 `commands.insert_resource(T { ... })` 在 Startup 中插入

### 5.3 系统函数

```rust
// 标准 Update 系统
fn my_system(
    time: Res<Time>,
    mut player_q: Query<&mut Transform, With<Player>>,
    mut reader: MessageReader<SomeEvent>,
    mut writer: MessageWriter<OtherEvent>,
) {
    let Ok(mut transform) = player_q.single_mut() else { return };
    // 逻辑...
}

// FixedUpdate 系统（物理、AI 等）
fn my_physics_system(
    fixed_time: Res<Time<Fixed>>,
    mut q: Query<&mut Velocity>,
) {
    // ...
}

// Startup 系统（一次性生成）
fn my_startup(
    mut commands: Commands,
    asset_server: Res<AssetServer>,
) {
    // 生成实体...
}

// 状态进入/退出系统
fn on_enter_level(/* ... */) { /* ... */ }
fn on_exit_level(/* ... */) { /* ... */ }
```

**规则：**
- 系统函数始终为 **私有**（不加 `pub`，除非被跨模块导入）
- 对外暴露的生成函数标记为 `pub(crate)`（如 `pub(crate) fn spawn_player(...)`）
- 命名：`{动词}_{对象}` 或 `{模块}_{动作}`
- 对 `.single()` / `.single_mut()` 始终用 `let Ok(...) = ... else { return };`，**禁止 unwrap**

### 5.4 系统注册位置

| Schedule | 适用系统 |
|----------|---------|
| `Startup` | 实体生成、数据加载、纹理生成 |
| `Update` | 输入处理、AI 巡逻、对话 UI、动画、HUD |
| `FixedUpdate` | 玩家物理、敌人移动、TD 模拟 |
| `PostUpdate` | 调试同步、最终 Transform 应用 |

**链式调用：** 有顺序依赖的系统用 `.chain()`：
```rust
app.add_systems(FixedUpdate, (
    player_input,
    player_physics,
).chain().run_if(in_state(GamePhase::Playing)));
```

### 5.5 实体生成

**禁止定义 Bundle 结构体**，直接用元组生成：

```rust
commands.spawn((
    Transform::from_xyz(0.0, 0.0, 0.0),
    Visibility::default(),
    Mesh3d(meshes.add(Cuboid::default())),
    MeshMaterial3d(materials.add(StandardMaterial::default())),
    Player,
    Speed(5.0),
    Name::new("Player"),
))
.with_children(|parent| {
    parent.spawn((
        Camera3d::default(),
        Transform::from_xyz(0.0, 1.9, -1.0),
        Name::new("Camera"),
    ));
});
```

**规则：**
- 每个实体必须有 `Name::new("描述名")`
- 子实体用 `.with_children(|parent| { ... })`
- 需要被关卡清理的实体加 `LevelEntity` 标记组件
- `Name` 命名规范：`"Player"`、`"NPC_名字"`、`"{ZoneId}_Enemy_{n}"`、`"Turret_{类型:?}"`

### 5.6 Query 模式

```rust
// 单实体查询（玩家、核心等唯一实体）
let Ok((transform, player)) = q.single() else { return };

// 多实体迭代
for (transform, enemy) in q.iter() { ... }

// 带过滤器的查询
Query<&Transform, (With<Player>, Without<Enemy>)>

// 子实体查询（排除父实体自身）
Query<&mut Transform, (With<Model>, Without<Player>)>

// 排除自身避免碰撞
Query<(&Transform, &CollisionShape), Without<Player>>
```

### 5.7 错误处理

```rust
// ECS 系统中 — let-else 提前返回（标准模式）
let Ok(player) = player_q.single() else { return };

// 文件加载 — match + error! 日志
match std::fs::File::open(&path) {
    Ok(file) => {
        match ron::de::from_reader::<_, SomeData>(file) {
            Ok(data) => { /* 成功 */ }
            Err(e) => { error!("解析失败 {:?}: {}", path, e); }
        }
    }
    Err(e) => { error!("打开失败 {:?}: {}", path, e); }
}

// 编译时数据 — include_str! + 回退默认值
let ron_str = include_str!("../../assets/data.ron");
match ron::de::from_str::<GameDatabase>(ron_str) {
    Ok(db) => commands.insert_resource(db),
    Err(e) => {
        error!("加载失败: {}", e);
        commands.insert_resource(GameDatabase::default());  // 回退
    }
}
```

**规则：**
- ECS 系统：**永远用 `let Ok(...) = ... else { return }`**，禁止 `unwrap()` / `expect()`
- 文件加载：用 `match` + `error!()`，不能阻断启动
- 日志级别：`info!`（正常事件）、`debug!`（调试详情）、`error!`（可恢复错误）
- 不要用 `warn!`（项目未使用）

### 5.8 命名规范

| 类别 | 约定 | 示例 |
|------|------|------|
| 组件 | PascalCase | `Player`, `MoveSpeed`, `DialogueTrigger` |
| 资源 | PascalCase | `Score`, `PlayerHealth`, `DialogueBank` |
| 事件/消息 | PascalCase + Event 后缀 | `StartGameEvent`, `CollectItemEvent` |
| 系统函数 | snake_case | `player_input`, `npc_patrol`, `handle_collect_item` |
| 插件 | PascalCase + Plugin 后缀 | `PlayerPlugin`, `GameUiPlugin` |
| 状态枚举 | PascalCase | `GamePhase`, `GameLevel` |
| 配置文件 | snake_case | `game_state.rs`, `debug_lighting.rs` |
| 模块 | snake_case，按功能命名 | `td/`, `toon/` |

### 5.9 模块可见性

- 默认 **私有**（不写 `pub`）
- 跨模块共享的系统用 `pub(crate)`
- Plugin 结构体用 `pub`
- 子模块中需要对外暴露的用 `pub mod` 或 `pub use`
- `mod.rs` 中统一 re-export：`pub use data::*;`

## 六、数据格式

### 6.1 RON 序列化

所有关卡、对话、配置数据使用 RON 格式：

```rust
// 定义
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct ZoneDef {
    pub name: String,
    #[serde(default)]
    pub floor_size: f32,
    #[serde(default)]
    pub collectibles: Vec<CollectibleDef>,
    // ...
}

// 加载（运行时）
let file = std::fs::File::open(&path)?;
let data: ZoneDef = ron::de::from_reader(file)?;

// 加载（编译时嵌入）
let ron_str = include_str!("../../assets/data.ron");
let data: GameDatabase = ron::de::from_str(ron_str)?;
```

**规则：**
- 数据定义要加 `#[serde(default)]` 允许字段省略
- 编译时加载的数据（游戏平衡、关卡布局）用 `include_str!`
- 运行时加载的数据（对话、区域）用 `fs::read_dir` 遍历 `assets/` 目录

### 6.2 坐标约定

- Y 轴向上（Bevy 默认）
- 位置用 `(f32, f32, f32)` 元组在 RON 中表示
- 颜色用 `(f32, f32, f32)` RGB 三元组（0.0 ~ 1.0）

## 七、关键设计模式

### 7.1 输入意图分离

```
用户按键 → MoveIntent 组件（意图层） → player_physics 系统（执行层）
```

输入系统只写 `MoveIntent.world_direction`，物理系统读取并应用。两个系统通过 `.chain()` 保证顺序。

### 7.2 LevelEntity 清理标记

每个关卡生成的实体都打上 `LevelEntity` 标记，关卡退出时统一删除：
```rust
fn cleanup_level(query: Query<Entity, With<LevelEntity>>, mut commands: Commands) {
    for entity in query.iter() {
        commands.entity(entity).despawn_recursive();
    }
}
```

### 7.3 碰撞作为函数库

`collision.rs` 不是 ECS 系统，而是纯函数库：
```rust
pub fn find_ground_y(pos: Vec3, shapes: &Query<(&Transform, &CollisionShape), impl QueryFilter>) -> Option<f32>
pub fn push_out_horizontal(pos: Vec3, radius: f32, obstacles: &Query<(&Transform, &CollisionShape), impl QueryFilter>) -> Vec3
```

调用方自行传入 Query 参数，保持碰撞逻辑与 ECS 解耦。

### 7.4 关卡生成直通车

```
LevelPlugin::OnEnter(Level1)
  → spawn_level1
    → load_zones (assets/zones/grassland.ron)
      → spawn_zone
        → 生成地面/墙壁/平台/NPC/收集品/敌人
```

## 八、不在本项目的规范

以下模式**不应**被采用，因为它们不是本项目的约定：

- **Bundle 结构体** — 项目不使用，直接用元组 spawn
- **`.unwrap()` / `.expect()`** — 生产代码中禁止，ECS 系统统一用 `let Ok(...) = ... else { return }`
- **`warn!()` 日志** — 项目不使用，用 `error!()` 替代
- **`.add_event()` / `EventWriter` / `EventReader`** — 已升级为 `.add_message()` / `MessageWriter` / `MessageReader`
- **`default()` + 手动 clone** — 用 `#[derive(Default)]` 代替

## 十、快速上手检查清单

给 AI 或新开发者的自检单，提交代码前逐项确认：

- [ ] 新功能是否定义为独立的 `Plugin` 结构体？
- [ ] 组件是否加了 `#[derive(Component)]`（必要时加 `Reflect`）？
- [ ] 资源是否加了 `#[derive(Resource)]`？
- [ ] 事件是否用了 `#[derive(Message)]` + `MessageWriter`/`MessageReader`？
- [ ] 生成实体是否都加了 `Name::new(...)`？
- [ ] 系统函数是否私有（不加 `pub`）？
- [ ] `.single()` / `.single_mut()` 是否用 `let Ok(...) = ... else { return }` 处理？
- [ ] 有无 `unwrap()` / `expect()` 调用？（应该为零）
- [ ] 游戏系统是否加了 `.run_if(in_state(GamePhase::Playing))`？
- [ ] 新文件是否在 `main.rs` 中声明了 `mod xxx`？
- [ ] 新插件是否在 `main.rs` 中注册了 `.add_plugins(XxxPlugin)`？
- [ ] 生成的需要清理的实体是否加了 `LevelEntity` 标记？
- [ ] 代码是否通过了 `cargo fmt` 和 `cargo clippy -- -D warnings`？
