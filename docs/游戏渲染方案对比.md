## 二、默认 PBR（当前使用）

### 2.1 原理

Bevy 内置的 **Physically Based Rendering**（基于物理的渲染），使用标准光照模型：

```
PBR 光照 = 环境光 + 漫反射 (Lambert) + 镜面反射 (GGX) + 菲涅尔
```

- 材质参数: `base_color`, `roughness`, `metallic`, `reflectance`
- 自动处理: 阴影、环境贴图、HDR 色调映射

### 2.2 代码示例

```rust
// PBR 标准材质 — 最简单的用法
commands.spawn((
    Mesh3d(meshes.add(Cuboid::default())),
    MeshMaterial3d(materials.add(StandardMaterial {
        base_color: Color::srgb(0.2, 0.6, 1.0),
        roughness: 0.3,           // 0=镜面, 1=磨砂
        metallic: 0.0,            // 0=非金属, 1=金属
        ..default()
    })),
));
```

### 2.3 优缺点

| 优点 | 缺点 |
|------|------|
| 零配置，Bevy 内置 | 画面偏"通用"，缺乏风格辨识度 |
| 性能好，移动端可用 | 暗部偏灰，没有艺术化阴影 |
| 材质参数直观 | 高光/阴影过渡完全物理化，无法艺术操控 |
| 与 Solari 光追兼容 | 远处物体缺乏视觉重点 |

### 2.4 适合场景

- 原型阶段快速出画面
- 不想花时间调渲染风格
- 后面可能切换到光追

## 三、三渲二 / 卡通渲染

### 3.1 原理

三渲二（Cel Shading / Toon Shading）将连续光照 **离散化为几个层级**，模拟二维动画的手绘感：

```
传统 PBR:  光强 0.0 ──────────────────→ 1.0  (连续渐变)
三渲二:    光强 0.0 ──▶ 暗面 ──▶ 中间调 ──▶ 亮面  (阶梯离散)
```

核心组成：
- **Ramp Texture**（渐变映射纹理）：用 1D 纹理将光照分为 2~5 个色阶
- **Specular**（高光）：硬边高光块，不自然扩散
- **Outline**（描边）：物体边缘有黑色描边线

### 3.2 实现方案对比

#### 方案 A：Bevy ExtendedMaterial（本项目之前使用）

```rust
// 自定义材质扩展 — 挂到 StandardMaterial 上
#[derive(Default)]
struct ToonExtension {
    ramp_texture: Handle<Image>,      // 阶梯度纹理
    spec_threshold: f32,              // 高光阈值 (0~1)
    spec_smoothness: f32,             // 高光边缘硬度
    spec_color: Vec4,                 // 高光颜色
    toon_enabled: u32,                // 开关
}

impl MaterialExtension for ToonExtension {
    // 绑定到 StandardMaterial 的 shader 管线
}

type ToonMaterial = ExtendedMaterial<StandardMaterial, ToonExtension>;
app.add_plugins(MaterialPlugin::<ToonMaterial>::default());
```

- **优点**: 复用 Bevy PBR 管线，阴影/环境光自动处理
- **缺点**: 需要写 WGSL shader，与 Bevy 版本耦合

#### 方案 B：自定义 Shader 材质（独立）

```rust
// 完全自定义的 shader — 不依赖 StandardMaterial
struct CelMaterial {
    color: Color,
    ramp: Handle<Image>,
    outline_color: Color,
    outline_width: f32,
}

impl Material for CelMaterial {
    // 完整的 vertex + fragment shader
    fn vertex_shader() -> ShaderRef { "shaders/cel_vertex.wgsl".into() }
    fn fragment_shader() -> ShaderRef { "shaders/cel_fragment.wgsl".into() }
}
```

- **优点**: 完全控制，不受 Bevy 管线约束
- **缺点**: 需要重写阴影、环境光等逻辑

#### 方案 C：后处理（Post-Processing）

```rust
// 在后处理阶段对屏幕做色调分离
app.add_plugins(PostProcessPlugin);
// 用 compute shader 将连续色调映射为 N 个色阶
```

- **优点**: 一次配置全局生效，不改材质
- **缺点**: 精度损失、描边难以实现

### 3.3 描边实现

| 方法 | 原理 | 效果 | 性能 |
|------|------|------|------|
| **倒转法** (Inverted Hull) | 渲染背面的放大模型，涂黑色 | 粗描边，风格强 | 2x 顶点数 |
| **后处理边缘检测** | Sobel 算子检测深度/法线断层 | 细描边，自适配 | GPU 开销 |
| **几何着色器** | 沿法线方向挤出边条 | 中等 | 中等 |

本项目之前使用倒转法（`src/toon/outline.rs`）。

### 3.4 优缺点

| 优点 | 缺点 |
|------|------|
| 强烈的视觉风格 | 需要写 shader 代码 |
| 不受光照变化影响，画面稳定 | 与光追不兼容 |
| 角色表情/特征更突出 | 需要调 ramp 纹理和阈值 |
| 契合日式 RPG / 动作游戏 | 场景复杂度受风格限制 |

### 3.5 调参关键

| 参数 | 效果 |
|------|------|
| ramp 纹理 2 阶 vs 5 阶 | 阶数越少越"二次元"，越多越接近 PBR |
| `spec_threshold` 0.3 vs 0.9 | 0.3=到处高光，0.9=仅亮面有高光 |
| `outline_width` 0.01 vs 0.06 | 细=精致, 粗=漫画感 |
| 描边颜色 纯黑 vs 深色 | 纯黑=动画感，深棕/深蓝=柔和 |

## 四、像素风格渲染

### 4.1 原理

**不是** 简单降低分辨率，而是通过以下手段系统性地营造像素感：

1. **低分辨率渲染**：渲染到小 Render Target（如 320×180），再放大
2. **色板限制**：限制可用颜色数量（如 16 色或 32 色）
3. **禁用纹理过滤**：`sampler = nearest` 保持像素颗粒感
4. **低帧率动画**：动画关键帧间隔大（如 4-8 fps 切换帧）
5. **抖动（Dithering）**：用 Bayer 矩阵模拟更多色调

### 4.2 实现方案

#### 低分辨率渲染（推荐入门方案）

```rust
// 1. 创建低分辨率 Render Target
let render_target = Image::new_fill(
    Extent3d { width: 320, height: 180, depth_or_array_layers: 1 },
    TextureDimension::D2,
    &[0; 320 * 180 * 4],
    TextureFormat::Rgba8UnormSrgb,
);

// 2. 渲染场景到这个低分辨率目标
// 3. 放大到窗口 (Nearest 采样)
// 窗口 1920×1080，渲染目标 320×180 → 6× 像素颗粒

// Bevy 中配置:
app.add_plugins(DefaultPlugins.set(WindowPlugin {
    primary_window: Some(Window {
        resolution: (640.0, 360.0).into(),
        ..default()
    }),
    ..default()
}));
```

#### 色板后处理

```wgsl
// shaders/palette.wgsl — 将颜色映射到最近色板色
@group(0) @binding(0) var input_texture: texture_2d<f32>;
@group(0) @binding(1) var palette: texture_2d<f32>;  // 16×1 色板纹理

@fragment
fn palette_fragment(in: VertexOutput) -> @location(0) vec4<f32> {
    let color = textureSample(input_texture, nearest_sampler, in.uv);
    // 找到色板中最近的颜色
    var best = vec4<f32>(0.0);
    var best_dist = 999.0;
    for (var i = 0u; i < 16u; i++) {
        let p = textureLoad(palette, vec2<i32>(i32(i), 0), 0);
        let d = distance(color.rgb, p.rgb);
        if d < best_dist { best = p; best_dist = d; }
    }
    return best;
}
```

#### 抖动（Dithering）

```rust
// 常见的 Bayer 2×2 或 4×4 矩阵
const BAYER_4X4: [[f32; 4]; 4] = [
    [0.0/16.0,  8.0/16.0,  2.0/16.0, 10.0/16.0],
    [12.0/16.0, 4.0/16.0, 14.0/16.0, 6.0/16.0],
    [3.0/16.0,  11.0/16.0, 1.0/16.0, 9.0/16.0],
    [15.0/16.0, 7.0/16.0, 13.0/16.0, 5.0/16.0],
];
// 在 shader 中用屏幕坐标取 Bayer 值，与颜色阈值比较
```

### 4.3 优缺点

| 优点 | 缺点 |
|------|------|
| 性能极好（低分辨率 + 简化 shader）| 文字/UI 在低分辨率下可读性差 |
| 强烈的复古风格 | 不适合精细的 3D 模型 |
| 美术资产制作快（像素画） | 3D 场景的深度感减弱 |
| 契合独立游戏/怀旧定位 | 玩家群体可能觉得"画面差" |

### 4.4 适合场景

- 恐怖游戏（低分辨率增加不安感）
- RPG Maker 风格 3D 游戏
- 体素/Voxel 游戏
- 移动端低配设备

## 五、真实渲染（光追）

### 5.1 原理

使用光线追踪（Ray Tracing）计算光照，每条光线模拟真实物理：

```
传统光栅化: 相机 → 投影到 2D → 每个像素查"最上面"的三角形 → 算光
光线追踪:   相机 → 发射光线 → 光线弹射 → 收集沿途光照 → 叠加
```

本项目使用 **Bevy Solari** 插件。

### 5.2 当前集成状态

```rust
// main.rs
app.add_plugins(SolariPlugins);  // 常驻，不影响 PBR 渲染

// 仅使用 StandardMaterial（不支持自定义材质扩展）
// Solari 关卡: GameLevel::Solari — 按 6 键进入
```

### 5.3 优缺点

| 优点 | 缺点 |
|------|------|
| 画面最逼真 | GPU 要求高（需 RT 核心） |
| 间接光照自动正确 | 不兼容自定义材质扩展 |
| 反射/折射物理正确 | 移动端不可用 |
| 适合展示和高端 PC | 开发迭代慢（重编译 shader） |

### 5.4 性能分级

| GPU 等级 | 建议 |
|----------|------|
| RTX 4060+ | 全效果 + 1080p~1440p |
| RTX 3060 | 中效果 + 1080p |
| GTX 1660 | 低效果或关闭光追 |
| 集成显卡 | 不可用，回退 PBR |

## 七、选型决策指南

```
你的游戏是什么类型？
    │
    ├── 动作冒险 / 日式 RPG
    │   └── 推荐: 三渲二
    │       理由: 角色突出、画面稳定、风格化强
    │
    ├── 写实 FPS / 模拟器
    │   └── 推荐: PBR + 光追（高端） / PBR（通用）
    │       理由: 物理准确的光照是体验的一部分
    │
    ├── 恐怖游戏
    │   └── 推荐: 默认 PBR + 低环境光 或 像素风
    │       理由: 低能见度制造紧张，像素风增加不安感
    │
    ├── 独立 / 复古 / 体素
    │   └── 推荐: 像素风
    │       理由: 低成本高风格辨识度
    │
    ├── 休闲 / 策略 / 俯视
    │   └── 推荐: 默认 PBR
    │       理由: 快速开发、通用性高
    │
    └── 技术演示 / 画面展示
        └── 推荐: 光追
            理由: 最佳画面效果
```

### 混合方案

可以在同一游戏中按场景使用不同风格：

```
常规关卡 (1-5): 默认 PBR ← 当前状态
Solari 关卡:    光追
菜单/过场:      三渲二（后处理）
小游戏/怀旧层:   像素风
```

切换只需在 `OnEnter(GameLevel::Xxx)` 中加载对应渲染配置。

## 八、风格切换操作清单

### 8.1 从当前 PBR 切换到三渲二

```
□ 1. 恢复 src/toon/ 模块（当前在但未编译）
□ 2. main.rs: 加回 mod toon; use toon::ToonPlugin; ToonPlugin,
□ 3. level.rs: 
     □ 加回 use crate::toon::{ToonExtension, ToonOutline, ToonSettings};
     □ 加回 make_toon_material 函数
     □ spawn_zone 参数加回 materials 和 settings
     □ 材质调用改回 make_toon_material
□ 4. 调 ramp 纹理: assets/textures/ramp.png
□ 5. 调 ToonSettings 参数
□ 6. cargo check → cargo run 验证
```

### 8.2 从当前 PBR 切换到像素风

```
□ 1. 添加低分辨率渲染目标
□ 2. 添加色板后处理 shader
□ 3. 配置 Window 分辨率为 640×360
□ 4. 关闭所有纹理的 mipmap 和线性过滤
□ 5. 添加抖动后处理
□ 6. cargo check → cargo run 验证
```

### 8.3 从当前 PBR 切换到光追

```
□ 1. 确认 SolariPlugins 已注册（当前已注册）
□ 2. 确保所有材质使用 StandardMaterial（当前符合）
□ 3. 按 6 键进入 Solari 关卡测试
□ 4. 如需主关卡也光追: 将 spawn_zone 改为使用 Solari 光照
```

### 8.4 回退到默认 PBR（当前状态）

```
不需要操作 — 当前已经是默认 PBR。
如果之前切到三渲二:
□ 1. 移除 main.rs 的 ToonPlugin
□ 2. level.rs 所有 ToonMaterial → StandardMaterial
□ 3. 移除 ToonOutline 组件
□ 4. cargo check
```
